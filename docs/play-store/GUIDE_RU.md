# Как выложить «Волан» в Google Play: пошаговое руководство

Всё, что можно подготовить без вашего аккаунта, уже готово: приложение (target API 36), сборка `.aab`, политика конфиденциальности,
тексты и графика. Вам остаётся завести аккаунт, создать ключ загрузки, загрузить файл и заполнить формы — тексты и ответы берите из
`docs/play-store/LISTING.md`, картинки — из `docs/play-store/graphics/`.

Актуально на 25.11.2026 (проверено по официальной справке Google Play Console). Правила меняются — если интерфейс отличается,
ориентируйтесь на смысл шага.

## Что нужно знать заранее

* Новые приложения загружаются как **Android App Bundle (.aab)** с включённой **подписью Play App Signing**.
* Приложения должны иметь **target API 36 (Android 16)** — у нас так и есть.
* **Личный аккаунт**, созданный после 13.11.2023, обязан перед выпуском в production пройти **закрытое тестирование: не менее 12 тестировщиков, подписавшихся (opt-in) на тест, непрерывно 14 дней**. Только потом можно подать заявку на production. Это самый долгий этап.
* Аккаунт разработчика стоит **25 долларов США**, разовый платёж.
* Приложение должно иметь **политику конфиденциальности по публичной ссылке** — она готова: https://rahim004.github.io/badminton-/privacy.html (проверьте, что открывается).

## Честное предупреждение про оплату из России

Регистрация и оплата **могут не получиться из России**: из-за региональных ограничений карты российских банков (Visa/Mastercard/МИР) для оплаты Google
обычно не работают, а страна карты должна совпадать со страной профиля платежей. Сам список стран для регистрации разработчиков
и способы оплаты Google меняет, и я не могу гарантировать актуальность из этого окружения — смотрите справку «Страны, в которых можно зарегистрироваться как разработчик» в Play Console.
Что можно сделать: оплатить картой банка страны, где вы легально живёте и которую поддерживает Google (профиль платежей создаётся на эту же страну);
не пытайтесь обходить ограничения подложными данными — аккаунт могут заблокировать, а деньги не вернуть.
Если не получается — есть **RuStore** (российский магазин приложений) как альтернатива для аудитории в России; условия публикации, требования к приложению и подписи
в нём свои, смотрите в его документации для разработчиков (я их здесь не проверял). Сборка `Volan.apk` из GitHub Release подходит как исходный файл для таких магазинов,
но требования к подписи и версии нужно уточнить у магазина.

## Этап 0. Один раз подготовить ключ загрузки и секреты

Откройте `tools/make-upload-key.md` и выполните шаги 1–5: создать ключ, добавить 4 секрета в GitHub, прогнать сборку и убедиться, что получился
`Volan.aab` (а не `Volan-NOT-FOR-PLAY.aab`).

## Этап 1. Регистрация аккаунта разработчика

1. Нужен аккаунт Google (лучше отдельный, под приложение) и телефон для кода. Откройте https://play.google.com/console/signup .
2. Выберите **«Личный» (Personal)** тип аккаунта — подойдёт физлицу. («Организация» требует DUNS-номер и юрлицо, и правило «12 тестировщиков × 14 дней» к ней не применяется, но для этого нужно юрлицо.)
3. Заполните имя, адрес (он может отображаться в магазине в карточке разработчика — смотрите подсказки на странице), e-mail для связи, телефон.
4. Оплатите **25 $** (см. предупреждение выше).
5. **Подтверждение личности**: загрузите документ, удостоверяющий личность (паспорт/права, как предложит Google), возможно, селфи. Проверка занимает от нескольких часов до нескольких дней.
6. Подтвердите устройство Android: Google для личных аккаунтов может попросить подтвердить телефон и Android-устройство (через приложение Play Console) — следуйте подсказкам на экране.
7. Дождитесь письма об активации аккаунта.

## Этап 2. Создать приложение

1. Play Console → **Создать приложение** (Create app).
2. Название: `Волан: бадминтон` (потом можно изменить). Язык по умолчанию: русский.
3. Тип: **Игра**. Бесплатное. Поставьте галочки с принятием правил (Developer Program Policies) и законов экспорта США.
4. На панели слева откроется список задач «Настройка приложения» — по ним идём дальше.

## Этап 3. Заполнить разделы (всё из LISTING.md)

Панель управления → **Настройка приложения (Set up your app)**:

1. **Политика конфиденциальности** (App content → Privacy policy): вставьте `https://rahim004.github.io/badminton-/privacy.html`.
2. **Доступ к приложению**: «Все функции доступны без ограничений» (входа нет).
3. **Реклама**: «Нет, приложение не содержит рекламы».
4. **Рейтинг контента**: пройдите анкету IARC — готовые ответы в `LISTING.md`, раздел «Анкета возрастного рейтинга».
5. **Целевая аудитория и контент**: выберите 13–15, 16–17, 18+ (детские группы не выбирать) — объяснение там же.
6. **Безопасность данных**: заполните по таблице из `LISTING.md`.
7. **Рекламный идентификатор**: «Нет».
8. Остальное («Государственное приложение», «Финансовые функции», «Здоровье», «Новости» и т. п.) — «Нет».
9. **Категория и контакты** (Store settings): тип «Игра», категория **Спорт**, теги из списка, e-mail разработчика, сайт.
10. **Главная страница в Google Play (Main store listing)**: название, краткое и полное описание — копируйте из `LISTING.md`;
    иконка `graphics/icon-512.png`; рекламный баннер `graphics/feature-graphic-1024x500.png`; скриншоты телефона из `graphics/screenshots/phone-*.png`
    (минимум 2, загрузите все 6; альбомные и планшетные — по желанию). Добавьте английский перевод («Управление переводами» → English) с английскими текстами.

## Этап 4. Загрузить .aab

1. Соберите релиз. Поднять версию: `src/version.js` → `VERSION = '1.0.1'` (для Play каждый новый файл должен иметь **больший versionCode**; он считается из версии: 1.2.3 → 10203).
2. `node tools/gen-sw.mjs`, закоммитить и отправить в `main`.
3. GitHub → **Actions → Release → Run workflow** (ветка `main`). Поставьте галочку **publish**, чтобы файлы попали в GitHub Release, либо скачайте артефакт `volan-android` из запуска.
   Проверьте, что среди файлов есть **`Volan.aab`** (не `NOT-FOR-PLAY`). Первую версию 1.0.0 при необходимости можно загрузить как есть; версию в Play нельзя использовать повторно — при ошибке поднимайте патч-версию.
4. Скачайте `Volan.aab` (из Release или из артефактов — если артефакт, это zip с файлами внутри).
5. Play Console → **Тестирование → Закрытое тестирование** (Testing → Closed testing) → **Создать трек / Create track** (например, «Друзья») → **Создать релиз**.
6. **Play App Signing**: при первой загрузке Google предложит использовать подпись Google Play — **согласитесь** (она обязательна). Ваш ключ загрузки остаётся ключом загрузки.
7. Загрузите `Volan.aab`. Название релиза и заметки: например, «1.0.0 — первая версия, бадминтон против ИИ и онлайн с друзьями».
8. Нажмите **Сохранить → Проверить релиз → Начать развёртывание на закрытом треке**. Если Play Console показывает ошибки/предупреждения — прочитайте и исправьте. Предупреждение про отсутствие файла деобфускации можно игнорировать (код не обфусцирован).

## Этап 5. Закрытое тестирование: 12 тестировщиков на 14 дней

Правило: **минимум 12 человек должны быть подписаны на тест (opt-in) и оставаться подписанными 14 дней подряд** (следите, чтобы никто не отписался: подписанных должно быть не меньше 12 всё это время; точные правила подсчёта смотрите в справке Play Console). Берите с запасом: 15–20 человек.

1. На странице закрытого трека → вкладка **Тестировщики** → **Создать список адресов** или привязать **Google Группу**.
   * **Google Группа** (удобнее): создайте группу на https://groups.google.com , тип «Группа для общения», в настройках разрешите вступать по приглашению/по заявке; добавляйте людей через «Участники → Добавить». В Play Console укажите e-mail группы (например `volan-testers@googlegroups.com`).
   * Или **список e-mail** (до 2000 адресов): добавляйте адреса Gmail тестировщиков вручную.
   Важно: у тестировщика должен быть **аккаунт Google** (подойдёт любой, не обязательно Gmail) и **телефон на Android** (с iPhone нельзя; Chrome на компьютере — только для перехода по ссылке).
2. Скопируйте **ссылку для подключения (opt-in URL)** со вкладки «Тестировщики» и разошлите её.
3. Каждый тестировщик: открывает ссылку **в браузере/на телефоне под тем же аккаунтом Google**, нажимает **«Стать тестировщиком»**, затем по ссылке «Скачать в Google Play» **устанавливает приложение** и запускает его хотя бы раз.
4. Следите по Play Console: на панели «Требования для публикации» (Dashboard) показывается, сколько тестировщиков подписалось и сколько дней прошло.
5. Где взять 12 человек (честно и по правилам): друзья, семья, коллеги, одногруппники, чат/группа в Telegram и WhatsApp, соцсети («нужны 12 тестеров на 2 недели, взаимно протестирую ваше приложение»), сообщества и взаимообмен тестами для инди-разработчиков. Не покупайте «тестировщиков» у сервисов-накрутчиков и не используйте фейковые аккаунты — это нарушение правил и риск блокировки.
6. За эти 14 дней просите тестировщиков открывать игру, играть и писать замечания (в GitHub Issues или лично). Реальные отзывы пригодятся при подаче заявки.
7. Хорошая практика: выпустите хотя бы одно обновление теста за две недели (новая версия → новый `.aab`), чтобы показать, что вы учитываете отзывы.

## Этап 6. Заявка на production

1. Через 14 дней при ≥12 подписанных в Play Console → **Панель управления → «Подать заявку на доступ к production» (Apply for production)**.
2. Ответьте на вопросы: как проходило тестирование, сколько тестировщиков, какие отзывы получили и что изменили, готово ли приложение к выпуску. Пишите по существу и честно.
3. Google рассматривает заявку обычно до нескольких дней (в справке указан срок; иногда дольше). Получите письмо о решении.
4. После одобрения: **Production → Создать релиз** → выберите уже загруженный `.aab` (или загрузите новый) → отправьте на проверку. Первая проверка приложения может занять до нескольких дней (иногда дольше — для новых аккаунтов).
5. Если приложение отклонят, причина и рекомендации придут письмом и в разделе «Политики». Исправьте и отправьте снова.

## Этап 7. Выпуск обновлений

1. Внесите изменения в игру.
2. Поднимите версию в `src/version.js` (`VERSION = '1.0.2'`) — **обязательно**, иначе versionCode совпадёт с загруженным, и Play откажет.
3. `node tools/gen-sw.mjs` (обновить офлайн-кэш; тесты `node --test tests/*.test.mjs` и `python3 tests/browser.py` должны проходить).
4. Закоммитить и отправить в `main`.
5. GitHub → **Actions → Release → Run workflow** с галочкой **publish** — соберёт `Volan.apk`, `Volan.aab`, `Volan.exe`, `Volan.AppImage` и опубликует Release `v<версия>`. (Релиз по тегу `v1.0.2` тоже сработает: `git tag v1.0.2 && git push origin v1.0.2`.)
6. Скачайте `Volan.aab` и загрузите в Play Console: Production (или нужный трек) → **Создать релиз** → загрузить → **Сохранить → Проверить → Развернуть**.
7. Если меняется то, что игра передаёт по сети, обновите `privacy.html` и форму «Безопасность данных».
8. Веб-версия на https://rahim004.github.io/badminton-/ обновляется отдельно: после пуша в `main` GitHub Pages сам опубликует новые файлы.

## Если что-то пошло не так

| Проблема | Что делать |
|---|---|
| «Вы загрузили пакет, подписанный ключом, не совпадающим с ключом загрузки» | Первая загрузка зафиксировала ключ загрузки. Подписывайте теми же секретами; при потере — сброс ключа через Play Console |
| Файл называется `Volan-NOT-FOR-PLAY.aab` | Не заданы секреты подписи; см. `tools/make-upload-key.md` |
| «Код версии уже использован» | Поднимите `VERSION` в `src/version.js` (versionCode считается из версии) |
| Target API слишком низкий | Должен быть 36 — в `android/app/build.gradle` уже `targetSdk 36` |
| Отказ «Minimum functionality / Spam» | Опишите: игра работает офлайн (все файлы внутри приложения), нативная оболочка, вибрация, жест «Назад»; при необходимости приложите ссылку на GitHub |
| Расхождение политики и формы «Безопасность данных» | Сверьте `privacy.html`, `LISTING.md` (таблица данных) и форму |
| Приложение с GitHub (APK) не ставится поверх версии из Play | Нормально: разные подписи. Удалите одно и ставьте другое |
