# Свой ключ загрузки (upload key) для Google Play

Google Play принимает только `.aab`, подписанный **вашим секретным ключом загрузки**. В репозитории лежит публичный ключ
`android/volan-public.jks` (пароль в открытом виде) — он нужен только для APK «с GitHub». `.aab`, собранный им, **в Google Play
загружать нельзя**: ключ известен всем. Сборка в Actions без секретов называет такой файл `Volan-NOT-FOR-PLAY.aab`.

Нужно один раз сделать ключ и положить его в секреты репозитория. Дальше каждая сборка Release будет выдавать `Volan.aab`,
подписанный вашим ключом.

> Что такое «ключ загрузки». При включённой подписи Google Play (Play App Signing — она обязательна для новых приложений)
> Google хранит настоящий ключ подписи приложения, а вы подписываете загрузки своим ключом загрузки. Если ключ загрузки
> потеряется или утечёт, его можно сбросить через поддержку Play Console, а приложение не пропадёт. Но потеря не должна стать
> привычкой: сделайте резервную копию (см. ниже).

## 1. Создать ключ

Нужен JDK 17+ (команда `keytool` входит в него). Windows: в `cmd`/PowerShell; Linux/macOS: в терминале. Папку выберите вне репозитория.

```bash
keytool -genkeypair -v \
  -keystore volan-upload.jks \
  -alias volan-upload \
  -keyalg RSA -keysize 2048 -validity 10000
```

(в Windows PowerShell команду пишите в одну строку без `\`.)

Команда спросит:

1. **Пароль хранилища** (минимум 6 символов; придумайте длинный и запишите в менеджер паролей) — это `ANDROID_KEYSTORE_PASSWORD`.
2. Имя и фамилия, организация, город, страна — можно любые правдивые (`Rahim`, `Volan`, `RU`/`TJ`/`DE`…). Они видны в сертификате, не в магазине.
3. «Is CN=… correct?» — `yes`.
4. **Пароль ключа** — нажмите Enter, чтобы был такой же, как пароль хранилища (проще). Если задали другой — это `ANDROID_KEY_PASSWORD`.

Проверка и «отпечаток» (пригодится, если Play Console его попросит):

```bash
keytool -list -v -keystore volan-upload.jks -alias volan-upload
```

В выводе строка `SHA256:` — отпечаток вашего ключа загрузки.

## 2. Резервная копия

Файл `volan-upload.jks` и оба пароля сохраните минимум в двух местах (менеджер паролей + зашифрованная флешка/облако).
**Не добавляйте файл в git** и никому не отправляйте.

## 3. Превратить файл в текст для секрета

Linux:

```bash
base64 -w0 volan-upload.jks > volan-upload.jks.b64
```

macOS:

```bash
base64 -i volan-upload.jks | tr -d '\n' > volan-upload.jks.b64
```

Windows PowerShell:

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("volan-upload.jks")) | Set-Content -NoNewline volan-upload.jks.b64
```

Откройте получившийся файл `volan-upload.jks.b64` — это одна длинная строка. Её нужно целиком скопировать (без пробелов и переносов).

## 4. Добавить 4 секрета в GitHub

Репозиторий `Rahim004/badminton-` → **Settings** → слева **Secrets and variables** → **Actions** → вкладка **Secrets** →
**New repository secret**. Создайте четыре секрета (имена — точь-в-точь, в верхнем регистре):

| Имя секрета | Значение |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | длинная строка из `volan-upload.jks.b64` |
| `ANDROID_KEYSTORE_PASSWORD` | пароль хранилища из шага 1 |
| `ANDROID_KEY_ALIAS` | `volan-upload` (то, что после `-alias`) |
| `ANDROID_KEY_PASSWORD` | пароль ключа; если нажимали Enter на шаге 1, повторите пароль хранилища |

После этого файл `volan-upload.jks.b64` можно удалить (оригинал `.jks` оставьте в резервной копии).

## 5. Проверить, что подпись настоящая

Actions → **Release** → **Run workflow** (галочку publish не ставить) → дождаться зелёной сборки → открыть задачу **android**:

* В шаге «Ключ подписи» должно быть «APK и AAB будут подписаны ключом из секретов репозитория» (а не жёлтое предупреждение).
* В шаге «Проверка подписи и имена файлов» выводятся `Owner:` и `SHA256:` сертификата `.aab` — это должны быть ваши данные, а не `CN=Volan (public key)`.
* В артефактах (**volan-android**) лежит `Volan.aab`. Если файл называется `Volan-NOT-FOR-PLAY.aab` — секреты не подхватились (проверьте имена и значения), в Google Play такой файл загружать нельзя.

## 6. Важно знать

* APK из GitHub Release после перехода на свой ключ получит другую подпись, чем прежние APK: поверх старой установки он не встанет,
  нужно удалить старое приложение (профиль перед этим перенесите кодом из раздела «Профиль»). Приложение из Google Play подписывается
  отдельным ключом Google, поэтому APK с GitHub и версия из Play друг поверх друга не ставятся — это нормально.
* Менять ключ загрузки можно, но только через запрос в Play Console («Целостность приложения» → «Сбросить ключ загрузки»).
* Если секреты не заданы вообще, `.aab` всё равно собирается (для проверки, что сборка работает), но с пометкой `NOT-FOR-PLAY`.
